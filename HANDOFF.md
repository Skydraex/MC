# Handoff

Read this first. It is written for a Claude Code session running **locally** on the owner's
machine, with the Minecraft server reachable and a bot available — things the cloud sessions
that built this did not have.

---

## What this is

`Skydraex/MC` — a classic-style Minecraft prison server as a single Paper plugin.
Package `com.lukeprison.prison`, artifact `PrisonPlugin`.

- **Paper 26.2**, compiled for **Java 25**. On Java 21 the server starts and then refuses the
  plugin with `UnsupportedClassVersionError`, which reads like a broken plugin rather than an
  old JVM. Check this first if it will not load.
- Requires **Vault** plus an economy provider (EssentialsX).
- The owner's server lives at `C:\Users\lthar\Desktop\Prison Server`.
- `SETUP.md` in this repo covers installing it from scratch.

Everything — the world, hub, 26 mines, cell block, grounds, terrain — is generated by the
plugin on first boot. Nobody places blocks by hand.

## Working agreement

**Branch, always.** Develop on `claude/bold-feynman-gkuzmh`. CI is gated on `claude/**` so
`main` stays green. Push to the branch, wait for the run, only then merge to `main` — the
owner pulls jars from `main`'s artifacts and a red `main` means no jar.

**Never hand-edit the generated files.** `MapLayout.java` and `RankMineData.java` are output.
The source of truth is:

```
tools/layout_gen.py   all geometry, pure Python, no Minecraft dependency
tools/economy.json    rank costs, ore mixes, sell prices
tools/gen_java.py     bakes both into the two Java files
tools/map_check.py    validates the geometry; CI runs it before the build
```

After any layout change: `cd tools && python3 gen_java.py && python3 map_check.py`.

**There is no local compile.** The cloud sessions could not reach `repo.papermc.io`, so CI
was the only compiler. A local session probably *can* build — try `mvn -q package`. If that
works, use it; it is a far faster loop than pushing and waiting.

## Things that have broken repeatedly

These are the failure modes this codebase actually has. Worth knowing before changing
anything near them.

**Areas sealed off.** Openings used to be cut by whichever method built the wall. That failed
three separate times — all thirty wards, then the fishing lobby, then the green and all three
grounds — and each time the world looked finished and simply could not be entered. Doorways
are now *derived* from the validated layout (`MapLayout.DOORWAYS`) and cut in one pass in
`WorldBuilder.carveDoorways()`. **Do not go back to hand-carving them.**

**A validator that only ever passed.** `map_check.py` originally asked "do these rectangles
touch", which is true of two rectangles meeting at one corner. It now measures shared edge
length and walks the *doorway* graph, and its checks were negative-tested — deliberately
breaking the ring, detaching a shaft, narrowing a corridor — to confirm each one fails. If
you add a check, break something on purpose and confirm it catches it.

**Signs vanishing.** A wall sign with nothing solid behind it survives placement (the build
runs with physics off) and is culled on the next chunk revalidation. `applySigns()` now tries
the requested facing, then any backed facing, then a free-standing sign on a post, and logs
each outcome. An earlier version "fixed" this by skipping unsupported signs, which placed 18
and skipped 191 — silent and much worse.

**Spawning inside blocks.** Warps, lift landings and beds have all at some point put a player
inside geometry. `MapAuditor` checks every one of them now.

**Coordinate helpers reused across different rectangles.** `wallCoord(wall, rect, near)` was
written for the hub rect, where "near" means the hub's own edge; reused on a ward rect the
meaning inverts. That one bug sealed all thirty wards. The helpers are split into
`hubEdgeOn()` and `hubFacingEdge()` now — keep them separate.

## The audits — use these before asking the owner to look

Both run one tick after boot and log to console, and `/padmin audit` runs them on demand.

`MapAuditor` walks the built world: every doorway open and floored, every mine shaft clear
from ward to ring, the ring continuous, nothing that puts a player down leaving them inside a
block, every requested sign still present, every cell floored with a way in, no bedrock
visible from a walkway, no dark spots.

`SystemAudit` checks the plugin: every command in `plugin.yml` has a real executor (not
Bukkit's silent do-nothing fallback), everything `/help` advertises exists, Vault has an
economy behind it, every subsystem constructed, the rank ladder joins A→Z→FREE with ascending
costs and real Material names, crate tables, enchants, staff permission nodes.

**On the first audited boot it found 69 problems.** 191 of 209 signs missing and 449 dark
mine tiles were real and are fixed. 52 were the audit's own bug — it checked lift pads as
though they were standing positions, when a pad is the block you stand *on*. Worth
remembering: a noisy check buries the real findings.

## Design rules — these are the owner's, not suggestions

The target is a **2012–2015 era classic prison**, not OP prison. The owner supplied a long
specification to this effect and has been consistent about it.

- **One currency: dollars.** Tokens existed and were removed. Do not reintroduce a second
  currency.
- **Ordinary enchants only.** Efficiency, Fortune, Unbreaking, Haste, Deep Efficiency.
  Explosive and Auto-Smelt were removed deliberately — an enchant that clears a 3×3×3 per
  swing, or smelts for you, deletes the carry-it-back-and-sell-it half of the loop.
- **The loop is physical.** Mines are walked to (stair down, 160-block shaft, ring concourse
  every mine opens off). The enchanter is a place in the hub, not a command. Cage lifts exist
  as a fast alternative but walking is the intended route.
- **Nothing stupidly broken.** The owner's words. The crate ladder: ~12% uncommon, ~3.5%
  rare, 0.5% very rare, 0.1% jackpot. The 0.5% rung must beat what vanilla enchanting can
  produce, or it is not worth 1-in-200. Everything under 1% carries Mending.
  `CrateData.audit()` enforces weights totalling 1000 per crate, one weight per item across
  all crates, and the Mending rule.
- **Prestige stays.** It was kept deliberately when tokens went.
- **Immersion.** No bedrock visible anywhere. Outside areas are fine if decorated like a
  professional team built them.

On builds looking "professional": the owner supplied reference images and the lesson taken
was that it is depth, not ornament. `Architect.facade()` gives every building a projecting
plinth, pilasters on a module, a string course, recessed window reveals and a cornice, under
`pitchedRoof()`, standing on a `groundSkirt()`. A flat one-block plane reads as texture, not
masonry. Use those helpers rather than `detailedWall` for anything new.

**Staff ranks:** Helper → Moderator → Admin → Super Admin → Owner, in `StaffRank`. Anything
that puts an item or a balance into a player's hands is Super Admin or above, on purpose — it
is the one staff abuse that cannot be undone. `/padmin` shows only what the caller can run.

## Where things stand

Everything described above is on `main` and CI-green. **None of it has been verified in
game** beyond the startup audit — the sessions that wrote it could not reach a Minecraft
server. That is precisely what a local session with the bot is for.

**Worth checking first, in rough order of how likely I think they are to be wrong:**

1. **The mines.** The ore band dropped to y30–42 and caverns are 30 blocks tall with planted
   terraces and landscaped plots. Biggest visual change, least verified.
2. **The plateau, cliffs and moat.** Generator change. If the prison is sunk into or floating
   above the terrain it will be obvious.
3. **The cell block.** Third arrangement — an atrium with six galleries, 108 cells. The stair
   has been wrong twice before.
4. **The gatehouse and causeway** on the west wall.
5. **Signs.** Should now be ~200 placed with 0 impossible. Check the console line.

**Known outstanding:**

- The mines still do not match the owner's reference builds. Going further needs horizontal
  room, which means widening `MINE_GAP` in `layout_gen.py` — that pushes the ring out and
  lengthens every trip. The owner accepted a 160-block shaft for the current plot size;
  anything more needs asking.
- The Notion page is stale (see below).
- No in-game verification of the command surface beyond `SystemAudit`'s static checks.

## The bot

`.mcp.json` in this repo configures a mineflayer-based Minecraft MCP server
(`github:yuniko-software/minecraft-mcp-server`) against `localhost:25565` as `ClaudeBot`.

- **Needs ViaVersion + ViaBackwards on the server.** The bot speaks 1.21.11; the server is
  26.2. Without them it cannot connect at all.
- **Needs `online-mode=false`.** The bot has no Mojang account.
- **First launch is slow** — it clones and compiles. If MCP startup times out, launch with
  `MCP_TIMEOUT=120000 claude`.
- **What it sees is not what the owner sees.** ViaBackwards translates packets, it does not
  backport blocks. Materials newer than 1.21.11 — cherry and mangrove wood,
  `CHISELED_BOOKSHELF`, `PINK_PETALS`, `TINTED_GLASS` — arrive as substitutes.

So: trust the bot on **structure** (can I get from here to there, is this sealed, is this
drop survivable) and not on **appearance**. For appearance, ask the owner for a screenshot.
